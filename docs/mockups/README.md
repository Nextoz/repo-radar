# Mockups

Five screens, drawn before the site was built, using real data collected on
13-15 Nov 2026.

| File | Screen |
|---|---|
| `Main.dc.html` | Radar A: three lanes side by side (Breaking out, For you, Just discussed) |
| `RadarB.dc.html` | Radar B: one ranked table with tabs and filters |
| `Repo.dc.html` | Repo page: growth chart with the flag moment, why it was flagged, quality, signals, trust |
| `Xray.dc.html` | X-ray page: architecture map, files, labelled connections. The subject is this repository |
| `Scoreboard.dc.html` | Scoreboard: flagged repos, and the Trending repos the radar missed, with the reason |

**What is real:** repository names, star counts, growth curves, Trending and
Hacker News data. **What is a placeholder:** quality scores, fit scores and
AI-written text, shown in square brackets, because those stages did not exist
yet. Flag times are what the planned rule would have produced on the real
snapshots. Line numbers on the X-ray screen are illustrative.

The files are sources for a design canvas and do not render on their own in a
browser. `canvas.json` holds their layout on the canvas.

Open choice: Radar A or Radar B. See `docs/SPEC.md`, WP3.
